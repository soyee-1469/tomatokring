# t.ring 개발 전달 문서

토마톡 앱 안의 스마트링 서비스 **t.ring** 화면 목업입니다. 50~70대 사용자를 기준으로 만들었습니다.
이 저장소는 **화면·흐름·문구·규칙의 기준**이고, 데이터는 모두 샘플입니다. 실제 앱으로 옮길 때 아래 "목업 → 실제로 바꿀 곳"을 먼저 봐 주세요.

- 기준일: 2026-11-27 (`main` 최신 커밋)
- 화면 확인: `npm install && npm run dev` → http://localhost:5180/vitaling/home
- 배포: Vercel (`vercel.json`, 모든 경로 → `index.html`)

## 1. 기술 구성

명령: `npm run dev` (개발 서버) · `npm run build` (타입 검사 + 빌드) · `npm run lint` (oxlint)

## 4. 데이터 연동 구조 (확정된 가정)

- **측정**: 반지 제조사 **SDK**가 블루투스 연결, 측정 시작, 자동 측정 주기, 펌웨어, 측정 결과 서버 저장을 맡습니다. 홈의 '측정' 버튼은 앱 안에서 바로 동작합니다.
- **기록 조회**: 지난 기록, 바디 리듬, 이상 징후 판정은 반지 제조사 **API**로 받습니다.
- **고유번호**: 반지를 연결하면 자동으로 연동합니다. 사용자가 입력하는 화면은 없습니다.
- **우리 서버에 쌓는 것**: 포인트 지급 판정, 받은 기록, 컨디션 체크 응답, 식단 사진·분석 결과, 설문 참여.
- **이상 징후**: 판정 라벨과 메시지는 API 값을 그대로 보여 줍니다. 우리가 따로 건강 판정을 만들지 않습니다.
- **확인 필요**: 수면 중 자동 측정 원본(심박수·심박변이도·피부 온도·혈중 산소)을 SDK가 원본으로 주는지, 요약만 주는지.

## 5. 포인트 규칙

| 미션 | 금액 | 조건 | 주기 |
|---|---|---|---|
| 스트레스 | 20만 P | 하루 중 스트레스 지수 **30 이하** 기록이 하나라도 있으면 (자동·직접 측정 구분 없음) | 하루 1회 |
| 식단 | 20만 P | 식단 사진 업로드 (아침·점심·저녁 중 1회) | 하루 1회 |
| 걷기 | 20만 P | 하루 **8,000걸음 이상** | 하루 1회 |
| 수면 | 20만 P | 수면 기록이 있으면 (조건 없음) | 하루 1회 |
| 설문 | 500만 P | 월간 설문 참여 | 한 달 1회 |

- 코드: `REWARD_P`(`components/ClaimBanner.tsx`), `STRESS_REWARD_MAX`·`WALK_REWARD_STEPS`(`components/PointGuide.tsx`)
- 받기 버튼은 **홈 카드에만** 있습니다. 상세 화면은 맨 위 '포인트 Tip'으로 조건만 안내합니다.
- 일 단위는 자정에 초기화(`YYYY-MM-DD` 키), 설문은 달 단위(`YYYY-MM` 키) — `session.periodKey()`
- **설문은 아직 운영 전**: `src/survey.ts`의 `SURVEY_OPEN = false`입니다. 열 때 `true`로 바꾸고 `SURVEY_FORM_URL`에 구글 설문지 주소를 넣습니다. 운영 전에는 오늘의 미션 개수·금액에서 빠집니다.

### 오늘의 미션 카드 (홈 맨 위)

- 도장 5개의 상태:
  - 조건 전: 연회색
  - 받을 수 있음: 초록
  - 받음: 진한 회색 + 초록 체크
- 문장:
  - 받을 게 있으면: "지금 받을 수 있는 포인트 N P"
  - 받을 걸 다 받았으면: "N개 받았어요 · {조건 전 항목}은/는 아직 조건 전이에요"
  - 전부 받으면: "미션을 모두 완료했어요"
- 도장을 누르면 해당 카드로 스크롤합니다.

## 6. 바디 리듬 규칙

- **유효 기록 1회** = 하루에 유효 데이터가 2개 이상 기록되고, 그중 **수면 기록이 포함**된 날
- **7회**부터 점수, **14회**부터 추세(회복·피로도 흐름, 그 전 7일 비교, 7일 평균)
  - `RHYTHM_MIN_DAYS = 7`, `RHYTHM_TREND_DAYS = 14` (`session.ts`)
- 7회 전: 회색 반원 게이지(하루 = 가는 눈금 5개 묶음 × 7)와 "7일 중 n일 기록했어요"
- 점수 등급 (`rhythm.ts` `GRADE_BANDS`)

| 등급 | 점수 | 색 |
|---|---|---|
| 나쁨 | 0–34 | `#EE8C84` |
| 주의 | 35–49 | `#F2AE6B` |
| 보통 | 50–74 | `#EECB55` |
| 좋음 | 75–89 | `#93CF7F` |
| 최상 | 90–100 | `#78B4EE` |

- 맨 위 한 줄은 다음 순서로 있는 것 하나만 보여 줍니다.
  1. 어제와 차이
  2. 7일 평균과 차이
  3. 점수
- **7일 평균** = 어제부터 7일 중 **기록이 있는 날만** 평균 (`rhythm.recentAvg7`)
- **데이터 복원**: 로그아웃하면 이전 기록이 안 보이므로 마이 페이지에서 복원합니다.
  - 기간: 최근 7일 / 14일 / 30일 / 직접 선택
  - 직접 선택은 오늘 포함 **73일 전**부터 가능합니다.

## 7. 문구 원칙 (중요)

우리는 데이터를 받아 보여 주는 서비스입니다. **근거 없는 건강 해석·조언을 넣지 않습니다.**

- 쓸 수 있는 것: 값, 정상 범위 안/밖, 지난 7일 평균과 차이, 목표와 차이, 등급 이름
  - 예: "정상 범위(60–100bpm) 안이에요", "지난 7일 평균 76bpm보다 3bpm 높아요"
- 쓰면 안 되는 것: "~해 보세요", "~일 수 있어요", "쉬어 가세요", "마음이 편안해요" 같은 해석·권장·추측
- 예외: 기기 사용법(착용·연결·동기화), 안전 고지("의료기기가 아니에요", "불편함이 계속되면 전문가와 상의해 주세요")
- 서비스 이름은 **t.ring**입니다. 화면에 반지 제조사 앱 이름을 쓰지 않습니다.
- 용어:
  - 바디 리듬 · 회복 · 피로도
  - 심박수 · 혈중 산소 · 피부 온도 · 심박변이도 · 호흡수
  - 스트레스 지수(0–100, 낮을수록 좋음) · 걸음 수 · 이상 징후
  - 수면 시간 · 수면 효율 · 수면 단계

  - 받기 같은 주 동작은 큰 버튼입니다.

## 9. 목업 → 실제로 바꿀 곳

| 위치 | 지금 | 바꿀 것 |
|---|---|---|
| `src/session.ts` | localStorage에 상태 저장 | 서버 API + 로그인 계정 |
| `src/rhythm.ts` `dayBundle` | 날짜로 만든 샘플 점수 | 제조사 API의 바디 리듬·회복·피로도 |
| `src/measureLog.ts`, `src/steps.ts`, `src/meals.ts` | 샘플 측정값·걸음·식단 | SDK 측정값 / 우리 서버 기록 |
| `screens.tsx` 반지 연결 | 버튼 누르면 연결된 것으로 처리 | SDK 블루투스 연결·고유번호 자동 연동 |
| 식단 사진 | 기기에서 축소해 localStorage 저장 (`imageUtil.ts`) | 업로드 + AI 칼로리 분석 서버 |
| 이상 징후 | `signalDemo` 샘플 상태 | 제조사 API 판정 라벨·메시지 |
| `src/survey.ts` | 운영 전, 주소 없음 | 구글 설문지 주소 + 참여 확인 방법 |
| `src/shop.ts` | 임시 구매 링크 | 실제 판매 페이지 주소 |
| `src/termsDocs.ts` | 일반적인 내용의 초안 | **법무 검토 후 확정본** |
| 포인트 지급 | 화면에서 받음 처리만 | 서버 지급·중복 방지·적립 내역 |

**시연용 버튼**(마이 페이지의 기록 일수·이상 징후·배터리 전환)은 `src/dev/DemoControls.tsx`에만 있습니다. `import.meta.env.DEV`일 때만 그려서 배포 빌드에는 들어가지 않습니다. 지우지 않아도 됩니다.
